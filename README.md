# EU4 Save Analyser

把玩过的欧陆风云4（Europa Universalis IV）存档留作纪念的个人网站。
上传 / 删除存档、解析 `.eu4`、并在时间线上回放每个国家的版图、宗教、文化变化。

技术栈：**TypeScript 全栈** —— Node 后端 + React 前端，解析器是纯 TS 包，
零运行时依赖，可在 Node 或浏览器（Web Worker）中运行。

需求见 [`docs/requirements.md`](docs/requirements.md)，解析器细节见
[`packages/eu4-parser/README.md`](packages/eu4-parser/README.md)。

**线上站点**：<https://try-eu4-savemanager.pages.dev>（Cloudflare Pages：Root `apps/site`、Build 留空、Output `public`；完整步骤见 [`部署手册.md`](部署手册.md)）。

## 快速开始

需要 Node ≥ 22.18（直接运行 TypeScript，无需构建步骤）。

```bash
# 存档头部信息：日期、版本、玩家、DLC、模组、战役统计
pnpm info "存档示例/mp_俄罗斯1574_11_12.eu4"

# 列出顶层区块（按体积排序）
pnpm sections "存档示例/mp_俄罗斯1574_11_12.eu4"

# 查看某个区块（或区块内某个条目）的成员结构
pnpm dump "存档示例/mp_俄罗斯1574_11_12.eu4" countries RUS --limit 60

# 省份 / 国家列表
pnpm provinces "存档示例/mp_俄罗斯1574_11_12.eu4" --limit 20
pnpm countries "存档示例/mp_俄罗斯1574_11_12.eu4" --limit 20 --min-provinces 1

# 导出省份 -> 归属/宗教/文化表（阶段 3 地图渲染的输入）
pnpm map "存档示例/mp_俄罗斯1574_11_12.eu4" --out tmp/map.json

# 完整快照（JSON）
pnpm parse "存档示例/mp_俄罗斯1574_11_12.eu4" --out tmp/snapshot.json

# 把存档画成地图（政治 / 宗教 / 文化 / 发展度）
pnpm render

# 解析结果与游戏自身文件交叉校验
pnpm verify

# 运行测试
pnpm test
```

### 地图预览

`pnpm render`（当前状态）与 `pnpm timeline`（月度时间线）需要游戏本体的
`map/provinces.bmp`（5632×2048，像素 → 省份）、`map/definition.csv`
（省份 → RGB）与 `map/default.map`（`sea_starts` / `lakes`）。

**斜线 = 被占领 / 信仰不一致**，这是本项目的核心画法：

| 视图 | 底色 | 斜线 |
|------|------|------|
| 政治 | 该省**拥有国**的 `map_color` | 当前**占领国**（战时占领，尚未和谈割让）；**不含叛军** |
| 宗教 | 该省**本身的宗教**（取游戏官方色表） | 实际在场的信仰（被占领时取占领国，否则取拥有国）与省宗教不同时 |
| 文化 | 该省**本身的文化** | **无**（用户要求文化视图不画斜线） |
| 发展度 | 热力图：**越高越绿，越低越红** | 无 |
| 王朝 | 统治王朝的**生成色**（存档不提供王朝色表，见下） | **无** |
| 神罗 | 帝国**之外**与未殖民地块同为中性灰；帝国内部分别着色：皇帝 / 选帝侯 / 自由市 / 成员国 | **占领国不在帝国之内**时画斜线 |
| 战斗（陆战） | 白→红，**历史累计**：每个地块随战斗次数与惨烈度不断变红 | 无 |
| 战斗（海战） | **蓝→红**（同一累计口径），与陆战一眼可分 | 无 |

#### 王朝视图：颜色是算出来的

本机 268 个模组里没有任何一个提供王朝色表（`common/dynasties/` 不存在），
存档里的 `dynasty` 区块只是按 `culture_group` 分组的**随机名字池**。因此 683 个
王朝的颜色由**黄金角散列**按字母序下标确定性生成——同一个王朝每次渲染颜色一致，
不写死任何色值。

#### 神罗视图的依据

存档**没有**自由市名单，`government_name` 匹配 `free_city` 才识别出 10 个
（如 ULM = `german_free_city`）；成员国身份由首都所在省份推导（984 个首都中
129 个省份 `hre=yes`，与存档字段**完全一致**）；皇帝取 `empire` 区块的
`emperor` 与 6 条 `old_emperor` 记录，共 7 次更替。

**科技**与**思潮**没有时间线（存档不记录它们的变化：`countries/*/history`
全档仅 11 条科技事件，省份历史没有思潮字段），所以**不放在时间轴里**，
只按存档当日各画一张静态图：`tmp/preview/tech.png`（拥有国 adm+dip+mil 总和，
**相对着色**：最弱最红、最强国最绿）、`tmp/preview/institution.png`
（已接纳思潮数**相对着色**；正在接纳的省份在其底色上画高一级颜色的斜线）。

### 国家兴衰曲线

时间线底部有一张 SVG 曲线图，画存档当日**发展度前 12** 的国家，逐月给出
`base_tax + base_production + base_manpower` 之和（另附省份数曲线）。

发展度**只**由省份历史推出——收入/兵力/理念/正统性在存档里只有快照，
账本系列（`nation_size_statistics` 等）只有约 45 年滚动窗口，画不出 130 年。

这里有一个**必须注意的重放陷阱**：省份区块里存的是**战役最终**数值，所以重放
要从存档当日往回推。但 4,941 个省里有 **2,450 个**的归属只写在 `history` 里
**没有日期**的初始状态中，而不是写在 `1444.11.11` 的带日期事件里。只重放带日期
事件的话，这些省会在全部 1,562 个月里都停在 1574 年的归属上，曲线几乎是一条
直线（本存档表现为俄罗斯 1444 年 2,249 → 1574 年 2,426）。叠加初始状态后，
俄罗斯变成 **1444 年 111 → 1574 年 2,505**，这才是真实的兴衰形状。

### 叛军与"未结束的占领"

两个必须处理的存档怪癖：

* **叛军不画**。EU4 会在省份历史里长期保留 `controller=REB`——本存档有 84 个省
  自 1449/1454/1455 年起就被"叛军占领"了一百多年，在政治视图上表现为永不消失的
  红色斜线。叛军不是国家，因此解析时不作为占领方。
* **EU4 经常不记录占领的结束**。本存档有 **503 个省份**的重放结果与存档自带的
  `controller` 字段不一致（例如涅瓦：1478 年被叛军占领后历史就再无记录，而存档
  显示俄国控制）。历史是过去唯一的依据，但"现在"以存档字段为准，因此在存档日期
  追加一条修正事件。修正后最后一天的 `controller` 与存档 **4,941/4,941 完全一致**。

两处关键判定：

* **颜色**用「按日期解析」的国号——莫斯科在变身之前显示自己的颜色，
  1529.2.5 之后才变成俄罗斯的绿色；
* **是否算占领**则用「解析到最终国号」的身份判断——否则 MOS 与 RUS
  会被当成两个国家，把俄罗斯自己的省份标成"被俄罗斯占领"。
* 宗教斜线的规则：东正教国家拥有/占领东正教省份 → 保持东正教底色不画线；
  拥有/占领其他宗教省份 → 在该宗教底色上画东正教斜线。
  本存档 2,093 个省保持底色，763 个画斜线（此前因字典错位几乎全画）。
* **思潮数组是有序的**：只有前面全是 100 才算接纳了第 N 个。
  `[0,100,…]` 没接纳任何思潮；`[100,26,…]` 接纳了 1 个并正在接纳第 2 个；
  `[100,100,100,100,10,…]` 接纳了 4 个并正在接纳第 5 个。
  判定逻辑在 `packages/eu4-parser/src/institutions.ts`，有测试覆盖。

`pnpm render` 输出到 `tmp/preview/`（政治 / 宗教 / 文化 / 发展度 / 科技 / 思潮，
外加 1 张政治 1:1 放大图）。

`pnpm timeline` 输出到 `tmp/timeline/`：

* **`index.html`** —— 自包含的月度播放器（约 2.2 MB，含内嵌省份位图与事件日志）：
  拖动时间轴、播放（放完自动暂停并变为重播按钮）、**七种可随时间变化的主视图**
  （政治/宗教/文化/发展度/王朝/神罗/战斗），1:1 像素级渲染；
  科技与思潮为存档当日快照，按钮与主视图同排；
  底部为**列强榜前 15**、**城市发展度前 15**、**思潮发源地**三张表，
  以及**国家兴衰曲线**（可点图例隐藏单条曲线）
* `data.json` + `raster.png` —— 同一份数据，供将来真正的网站前后端消费
* `peak-*.png` —— 占领最多的那个月（1500+ 省份被占领时）的服务端快照
* **1562 个月度帧**（1444.11 → 1574.11），由单个存档回放得到

**为什么时间线是浏览器渲染而不是预渲染 PNG**：月度 × 多视图 = 上万张图，
体积不可接受。所以服务端只导出「省份位图 + 差分事件日志」，浏览器 canvas
逐帧回放——和 pdx tools 的做法一致。斜线画法在 `scripts/lib/paint.js`，
服务端 PNG 与浏览器共用同一份代码（内联时去掉 `export`），不会出现两套实现。

## 关键结论（影响后续设计）

1. **`.eu4` 里的中文不是 UTF-8。** 游戏用一种"字母流"编码：
   `<0x20` 的字节是转义标记，后跟 2 字节小端 UTF-16 码元，且需要按标记
   加回偏移量（`0x10`→0、`0x11`→−14、`0x12`→+2304、`0x13`→+2290）。
   细节与逆向过程见解析器 README。
2. **少数字符串仍是 UTF-8**（`save_game`、模组名），解析器会自动判别。
3. **省份 key 是负数**：`-1` 就是省份 1（斯德哥尔摩）。
4. **单个存档就包含完整时间线**（此前判断有误，已修正）：
   * `provinces/{id}/history` —— 每个省份从开局的带日期事件日志，
     示例存档 3,924 省 / 147,337 条事件，含 owner、controller（战时占领）、
     religion、culture、发展度、建筑、核心与宣称；
   * `previous_war` × 621 + `active_war` × 17 —— 每场战争的逐月分数、
     参战/退战日期、逐场战斗（地点省份、双方伤亡、指挥官、胜负）、和约条款；
   * `income_statistics` / `nation_size_statistics` —— 按国家按年的曲线，
     但只有约 45 年的滚动窗口。
   **所以"版图时间线"不需要多个存档**——把省份事件按日期前向回放即可。
5. **省份历史记的是当时的国号 tag**，改国号要额外解析
   `countries/{TAG}/history` 里的 `changed_tag_from`。示例存档有 17 次
   （莫斯科→俄罗斯、英格兰→大不列颠、勃兰登堡→普鲁士、日本……）。
   不做这步，1574 年的地图会把 380 个省份画成"莫斯科"。
6. **回放可被严格验证**：回放到存档当天，与存档自带的省份表
   owner / religion / culture **逐省 100% 一致**（2,856 / 3,269 / 3,269），
   这个校验已固化成回归测试。
