## 二、冻结的数据契约（所有任务照此实现，不许各自发挥）

### 2.1 `SaveRecord` 新增一个 `custom` 字段

编辑 `apps/site/src/api.ts`：

```ts
/** 一个主角国家：用户自定义，显示在目录页卡片上。 */
export interface Protagonist {
  /** 国家 TAG。规范化为大写，只保留 A-Z 0-9，长度 2–4。 */
  tag: string;
  /** 玩家名字，可以为空。 */
  player?: string;
}

/** 用户自定义的卡片信息；全部可选，缺省即"用解析出来的值/原始文件名"。 */
export interface SaveCustom {
  /** 自定义标题。空 = 退回原始文件名 name。 */
  title?: string;
  /** 自定义结档日期（自由文本，建议 1574.11.12）。空 = 用 info.campaignDate。 */
  endDate?: string;
  /** 自定义模组说明，一个字符串。空 = 用 info.mods 的个数。 */
  mods?: string;
  /** 主角国家，数组顺序即显示顺序；目录页最多显示前 3 个。 */
  protagonists?: Protagonist[];
}

export interface SaveRecord {
  // ...现有字段不动...
  /** 用户自定义信息。老记录没有这个字段，视为 {}。 */
  custom?: SaveCustom;
}
```

**`name` 保持原样**（原始文件名），不做标题用途——重新解析、去重、删除都靠它和 `id`。

### 2.2 `PATCH /api/saves/:id` 增加 `custom` 支持

现有 `updateSave()` 已经支持 `name` 与 `info` 的合并，照同样的风格加 `custom`：

- 请求体 `{ custom: {...} }`：**逐字段深合并**（`{ ...record.custom, ...patch.custom }`），只传想改的字段即可。
- 传 `custom: null` → 清空整个 `custom`（回到全默认）。
- 传某字段为 `""`（空字符串）或 `[]`（空数组） → **删除该字段**（回到默认），不是存一个空串。
- 清洗规则（服务端做，前端脏数据不许进库）：
  | 字段 | 规则 |
  |---|---|
  | `title` | 去首尾空白；超过 80 字符截断；空 → 删除 |
  | `endDate` | 去首尾空白；超过 20 字符截断；空 → 删除 |
  | `mods` | 去首尾空白；超过 200 字符截断；空 → 删除 |
  | `protagonists` | 必须是数组；每项取 `tag`/`player`；`tag` 转大写、剔除非 `[A-Z0-9]`、取前 4 位，长度 < 2 的项**丢弃**；`player` 去首尾空白、超 40 字符截断、可为空；**同 tag 只保留第一条**；最多 **20** 条（超出截断）；清洗后为空数组 → 删除该键 |
- 返回体与现有 PATCH 一致：`{ save: updated }`，并写回 `saves/<id>/meta.json` 与 `index.json`。
- **不影响** `status` 判定（现有那句"填 info 不能把 ready 降级"的逻辑保持不动）。
- `index.json` 损坏时的重建路径（`rebuildIndex`）不用改：它读 `meta.json`，`custom` 自然带出来。

### 2.3 新增 `GET /api/saves/:id`

查看页需要读单条记录（要为编辑面板填初始值），列表接口太重。

- `apps/site/src/api.ts` 新增 `getSave(id, request, env)`：找到返回 `{ save }`，找不到 404，**不需要令牌**（和列表同一级别，列表本来也不校验）。
- `apps/site/src/dev-server.ts`：在 `/^\/api\/saves\/([^/]+)(\/artifact|\/original)?$/` 那个分支里给 `GET` 加一条（现在的 `else` 直接 405）。
- `apps/site/functions/api/saves/[id].ts`：加 `export const onRequestGet`。
- 两处都要：本地开发走 dev-server，线上走 Pages Functions。

### 2.4 卡片元素 → 数据来源对照表（任务 2 严格按这个渲染）

| 卡片元素 | 取值 | 兜底 |
|---|---|---|
| 标题 | `custom.title` | `save.name`（原始文件名） |
| 缩略图 | `/saves/<id>/viewer/thumb.png`（任务 4 产出） | 灰色占位块；`<img onerror>` 时隐藏 |
| 主角旗帜/国家娘 | `custom.protagonists` 的前 3 个，按数组顺序横向排列 | 数组为空 → **整块不渲染**（不留空位） |
| 旗帜下方图注 | `${player}-${国名}`；国名查本地化表 | 查不到国名 → 用 TAG；`player` 为空 → 只显示国名 |
| 结档日期 | `custom.endDate` | `info.campaignDate` |
| 版本 | `info.version`（游戏版本，只读） | `—` |
| 模组 | `custom.mods` | `info.mods ? info.mods.length + ' 个' : '—'` |
| 次要信息（文件大小/加入时间/编号/省份/国家/战争/解析耗时） | 现有字段 | **保留但弱化**：放到卡片最下面一行小字，不要删（用户没说要删） |

**国名怎么查**：目录页已经能从 IndexedDB 拿到国名表——`game-folder.js` 的 `cachedTables()` 返回 `{ names, religions }`，配合 `game-localisation.js` 的 `localise(names, tag)`。没缓存（用户从没选过游戏目录）就**直接用 TAG**，不要为了查名字去弹选目录的框。

### 2.5 图片 URL 约定（不许新造路径）

- 旗帜：`/assets/flags/base/<TAG>.png`（原版）与 `/assets/flags/modded/<TAG>.png`（国家娘）。这套前缀查看页已经在用（`viewer.js` 里的 `FLAG_PREFIX`），任务 2 照抄同一套。
- 缩略图：`/saves/<id>/viewer/thumb.png`，**由 id 直接推导**，不新增 API 字段。
- 旗帜加载失败（模组没这个 tag）→ 该张旗帜换成 TAG 文字块（`onerror`），不要让卡片出现碎图标。

### 2.6 权限与令牌

- 写操作（PATCH）走 `<script>` 现成的规矩：请求头带 `x-upload-token: <localStorage['catalogue.token']>`。
- 本地开发默认不校验口令（dev-server 见 `UPLOAD_TOKEN` 未设就放开）；线上必须有口令。
- 收到 401/403 → 提示「去目录页 ⚙ 里填上传口令」，**不要**静默失败。

用户报：**清 1683_08_09 档**里 **新东洲、香蜜湖、黎洲、北洋督司**（以及同一档的 墨法、文兰、平原省）都没有旗帜。

用户还报：**几乎所有制成品的右半色都是黄的**——殖民地旗应该「左半跟随宗主国的旗/国家娘，右半是该殖民地自己的颜色」。

### 根因（本对话已实测定位，任务里不用再猜）

1. 它们都是**动态殖民国家 tag**（`C11` 黎洲 / `C13` 北洋督司 / `C16` 香蜜湖 / `C17` 新东洲 / `C12` 墨法 / `C14` 文兰 / `C15` 平原省）。游戏本体 `gfx/flags` 里**没有** `C##`/`D##` 的旗美术，前端会按"殖民合成旗"兜底。
2. 合成旗由 `scripts/export-colonial-flags.ts` 生成，但它**只读一个写死的存档**：`存档示例/mp_俄罗斯1574_11_12.eu4`（脚本第 16 行），所以只产出了 `C00`–`C10` 共 11 面。
3. 实测扫描全部 10 份存档的 `colonialParent` 账本：**87 个殖民地 tag 在任何目录（base/modded/colonial/colonial-modded）里都没有旗**——清档 7 个、西班牙 1567 档 3 个、大汉 258 与大闽 971 档各 72~74 个。
4. **额外发现的坑（必须一起解决）**：`C##` 是**可复用的槽位**，同一个 tag 在不同存档里属于不同宗主。例：`C11` 在西班牙 1567 档是"佛罗里达"（宗主 SPA），在清 1683 档是"黎洲"（宗主 QNG）；`C13` 在 1567 档是"佛罗里德"（FRA）、在 1683 档是"北洋督司"（QNG）。**一个 tag 只存一张静态合成旗就会画错宗主**（把西班牙旗画给清朝殖民地）。所以必须做成 **parent-aware**：文件名里带上宗主，例如 `assets/flags/colonial/QNG-C11.png`。
5. 前端已经能拿到宗主：`DATA.colonialParent[tag]`（`app.js` 的卡片旗帜与 `viewer.js` 的 `applyFlag`/`heroFlagUrl` 都读得到）。
6. 复核用的小探针我留在 `tmp/find-flagless.js` 与 `tmp/colonial-audit.js`（`node tmp/colonial-audit.js` 会打印每份存档缺旗的殖民地清单与并集），可以直接拿来当改前/改后的对照。
7. **右半全黄的根因也定位了（实测）**：填充色来自 `hashColor(tag)`，而它是
   `h = (h*31 + code) >>> 0; hslToRgb(h % 360, 0.6, 0.45)`——多项式哈希的**低位**随 tag 字符近似线性变化，`% 360` 又只看低位，于是相邻 tag 的色相差不到几度：实测 `C00`–`C09` 色相 **43–52**、`C10`–`C17` **74–81**、`D00`–`D05` **284–289**；我采样了现有 11 面合成旗，右半全是 `#B8912E`…`#B8A52E`（就是用户看到的黄）。修法：取色相前先做一次**位混合**（murmur3 的 `fmix32`：`h^=h>>>16; h=Math.imul(h,0x85ebca6b); h^=h>>>13; h=Math.imul(h,0xc2b2ae35); h^=h>>>16;` 再 `>>> 0`）。我实算过：同样这 24 个 tag，混合后色相散布在 **10–353**，最小间隔只有 1°（C06 与 C11 撞）——可接受；想更均匀可以在同一存档内按 tag 排序后用黄金角 137.508° 分配。
8. **`hashColor` 在仓库里有两份定义，必须同时改、结果一致**：`scripts/lib/map-assets.ts`（第 171 行，离线面：`render-timeline.ts`/`render-map.ts`/`export-colonial-flags.ts` 都用它）与 `apps/site/public/viewer-build.js`（第 133 行，浏览器数据面）。两个数据面的颜色是要逐键比对等价的，**只改一份会让 `viewer-build.test.ts` 挂**。
9. **还有一处"没生成"的原因**：`export-colonial-flags.ts` 的 `sourceOf()` 只认 `.tga`/`.bmp` 宗主旗，**宗主旗是 PNG/JPEG 时直接返回 undefined → 这面合成旗被跳过**（脚本自己会把它记进 `skippedNoArt`）。更稳的做法是**不再从游戏目录取源，改用已经导出的** `apps/site/public/assets/flags/{base,modded}/<PARENT>.png` 当合成源（同一套 PNG、尺寸统一、也不再需要玩家装游戏）；代价是要在 `scripts/lib/flags.ts` 补一个最小 PNG 解码器（`scripts/lib/png.ts` 目前只有编码器，解码器只需支持非交错 8-bit RGB/RGBA + 5 种 filter，`node:zlib.inflateSync` 解压）。JPEG 宗主旗这一版可以先不处理，但要在回报里列出涉及的 tag。

# 第六轮（2026-09-19 方案修订：殖民地旗改成运行时叠加）

## 二十六、为什么可以、以及怎么改（本节修订第二十四节的前端部分）

**用户的方案**：不生成图片，直接**继承宗主旗**，在**右半边蒙一个色块**（"先继承宗主旗帜，再在其右半侧蒙一个图层"）。

**结论：可行，而且比预生成更干净。** 当初选预生成的理由是"要产出一张图"，而写图必须走 `canvas.toBlob`，`file://` 下本地图片会污染 canvas；**纯 DOM 叠加根本不写图，所以这个限制不存在**——它在托管页、离线自包含页、`file://` 直开三种情况下都能工作。

**改法（冻结，两个任务照这个写）**

1. **渲染结构**：凡是画旗帜的地方，把裸 `<img class="flag" data-tag>` 变成
   ```html
   <span class="flagBox"><img class="flag" data-tag="C11" src="…"><i class="flagTint" style="background:#b82e4c"></i></span>
   ```
   ```css
   .flagBox{position:relative;display:inline-block;line-height:0}
   .flagBox>img{display:block}
   .flagTint{position:absolute;left:50%;top:0;width:50%;height:100%;pointer-events:none}
   ```
   底色仍然透明，覆盖层正好压住右半。
2. **解析顺序（客户端，取代原来的三次 404 重试）**：
   `DATA.colonialParent[tag]` 有值 → `img.src = FLAG_PREFIX[flagSet] + <宗主>.png` **并挂上色块**；没有值 → 照旧用`<TAG>.png`；宗主旗也 404 → 沿用现在的行为（隐藏 / TAG 方块）。这样每个殖民地**只发一个图片请求**，而且宗主永远取自当前存档，天然 per-save 正确。
3. **色块颜色**：客户端自己算，**必须与构建侧同一个算法**（这样"旗右半的颜色"和"地图上这个殖民地的颜色"一致），算法冻结为：
   ```js
   function flagFill(tag) {
     let h = 0;
     for (const ch of tag) h = (h * 31 + ch.charCodeAt(0)) >>> 0;
     h ^= h >>> 16; h = Math.imul(h, 0x85ebca6b);
     h ^= h >>> 13; h = Math.imul(h, 0xc2b2ae35);
     h ^= h >>> 16;
     return hslToRgb((h >>> 0) % 360, 0.6, 0.45);   // 与现有 hashColor 同一套 HSL 参数
   }
   ```
   颜色对同一 tag 恒定、不随"配色"模式变化（旗子不该跟着地图配色模式变色）。
4. **要改的四个渲染点**：①`viewer.js` 的 `applyFlagSet()` / `onFlagMissing()`（列强榜表格与所有 `img.flag`）；②`viewer.js` 的 `paintHeroStrip()`（标题行主角旗帜排）；③`app.js` 的卡片主角旗帜（`protagonistsMarkup` + 它的 404 重试链）；④`viewer.js` 里其余按 `data-tag` 画旗的地方（有就一起）。
5. **旧产物退休**：`assets/flags/colonial*` 里那 22 个（全是黄的）不再需要——由任务 13′ 删除；`scripts/export-colonial-flags.ts` 与 `scripts/verify-flags.ts` 顶部加一段"已由运行时叠加取代"的说明（脚本保留，供以后想导出静态图时用），并把缺旗检查从 `verify:deploy` 里摘掉（新机制不会缺旗）。

**好处 / 代价**

| | 运行时叠加 | 预生成图片（原方案） |
|---|---|---|
| 新存档/新殖民地 | **立刻就有旗**，不用重跑脚本、不用重新部署 | 必须本地跑一次脚本 + 提交 + 推送 |
| 同一 tag 跨战役 | **自动正确**（宗主从当前存档取） | 靠 `<宗主>-<TAG>` 命名区分，极端情况撞色 |
| 离线页 / file:// | 可用（不碰 canvas） | 可用（读文件） |
| 请求数 | 1 张图 | 1~3 张（404 重试链） |
