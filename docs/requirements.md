# 需求记录

来源：用户 2026 年项目概述（原文摘要见下）。

## 项目目标

为个人欧陆风云4（EU4）存档做一个纪念性质的网站。玩完一个存档后这些存档
往往就失去意义了，希望把它们永久留存下来，并能回看自己打下的江山。

## 功能需求

| # | 需求 | 说明 |
|---|------|------|
| R1 | 存储多个存档文件 | 一个站点保存全部 `.eu4` 存档 |
| R2 | 上传存档 | 支持上传单个 / 批量 `.eu4` 文件 |
| R3 | 删除存档 | 可删除不再需要的存档 |
| R4 | 解析 `.eu4` | 读取存档内容，不依赖游戏本体运行 |
| R5 | 版图变化回放 | 在游戏时间线上完整表现每个国家的版图变化 |
| R6 | 多视图 | 除版图外，还应有宗教视图、文化视图等 |
| R7 | 国家详细数据 | 尽可能详细地展示各个国家的信息与数据 |
| R8 | 指导式开发 | 用户在过程中给出方向性指导 |

## 关键约束与推论

### C1 版图历史就在单个存档里（原判断已修正）

最初判断"单个存档只保存当前状态"，**这是错的**。实测表明：

* `provinces/{id}/history` 是从开局到当前日期的**带日期事件日志**，
  示例存档 3,924 个省份共 147,337 条事件，覆盖 owner、controller（战时占领）、
  religion、culture、发展度、建筑、核心与宣称；
* 逐帧前向回放到存档日期，能与存档自带的省份表 **100% 对得上**
  （owner 2,856/2,856、religion 3,269/3,269、culture 3,269/3,269）。

**因此 R5（版图变化回放）由单个存档即可满足**，无需多存档差分。
多存档合并仍有独立价值（跨存档续玩、去重），但不再是 R5 的前提。

推导时要注意：

* 省份历史记录的是**当时**的国号 tag。国家改国号（如莫斯科→俄罗斯，
  示例存档有 17 次）必须解析 `countries/{TAG}/history` 里的
  `changed_tag_from` 做别名映射，否则 1574 年的地图会把 380 个省份
  标成"莫斯科"。
* `controller` 字段给出**战时占领**状态，与 `owner` 区分开——这正是
  "谁占领了谁"的来源，可与 `previous_war` 的战斗记录交叉印证。

### C2 战争史的字段已确认

* `previous_war`（621 场）+ `active_war`（17 场），每场含
  `history`（逐月战争分数、`add/rem_attacker/defender` 参战退战日期）、
  `participants`、`original_attacker/defender`、`war_goal`、和约条款
  （`take_province` / `take_capital` / `annul_treaties` …）；
* `history` 内的 `battle` 条目含日期、地点省份 id、双方兵种/伤亡/
  指挥官/国 tag、胜负；示例存档共 3,172 场战斗（272 场海战）；
* 唯一没能确定的是 `outcome` 枚举语义（526/584 都是 2，且多数没存分数），
  因此代码只把它当不透明代码暴露，展示时改用和约条款与战斗结果。

### C3 长期曲线受限于滚动窗口

`income_statistics` / `nation_size_statistics` / `inflation_statistics` /
`score_statistics` 只有**约 45 年的滚动窗口**（示例：1530–1574）。
要画整局曲线，只能从省份历史与战争记录自行聚合。

### C6 渲染约定（占领斜线）

用户明确要求的表现方式：

| 视图 | 底色 | 斜线 |
|------|------|------|
| 政治 | 该省**拥有国**的颜色 | 当前**占领国**的颜色（战时占领，未和谈割让） |
| 宗教 | 该省**自身的宗教**颜色 | **拥有国的国教**颜色 |
| 文化 | 该省**自身的文化**颜色 | 拥有国的**主体文化**颜色 |
| 发展度 | 越高越绿、越低越红的热力图 | 无斜线 |

要点：

* `owner` 与 `controller` 的区分正是"谁占领了谁"的来源；两者相等则无斜线。
* **必须按国号别名解析后比较**：MOS 改名 RUS 之后，"被 RUS 占领的 MOS 省份"
  是同一个国家，不是占领。示例存档中不解析会把 1510 年的占领数从 500 虚报。
* 时间线精度为**月**（每 12 个月一个帧循环，共 1562 帧）。

### C7 时间线必须浏览器端渲染

月度 × 4 视图的预渲染 = 上万张 PNG，不可接受。因此：

* 服务端只产出「省份位图（id 编码进 R/G 通道）+ 差分事件日志 + 调色板」；
* 浏览器用 canvas 逐帧回放，服务端 PNG 与浏览器共用**同一份**绘制代码
  （`scripts/lib/paint.js`，内联时去掉 `export`），避免两套实现漂移；
* 用事件差分而不是逐月快照：58,826 条事件即可表示 1562 帧，
  自包含 HTML 仅 1.8 MB。

### C8 地图渲染需要游戏本体资源

要把省份 id 渲染成地图，需要 EU4 安装目录下的：

* `map/provinces.bmp` —— 每个像素对应一个省份（按颜色索引）
* `map/definition.csv` —— 省份 id ↔ RGB 颜色 ↔ 内部名
* `map/default.map` —— `sea_starts` / `lakes` 列表，用来区分海洋与湖泊

本机已确认存在：`D:\Software\Steam\Steam\steamapps\common\Europa Universalis IV`。
网站需要一个"指向游戏目录 / 上传这几个文件"的一次性设置步骤，
且必须注意：**用户装了模组（示例存档启用了 11 个），模组可能改动省份划分**，
所以版本与模组清单需要一并记录。

### C5 中文显示

示例存档使用了中文模组（"Chinese Language Mod for 1.37" 等）。
存档内的省份名、玩家昵称本身已是中文，可直接使用；
但国家名、宗教名、政府名等是**本地化 key**（如 `russian_monarchy`、
`orthodox`），需要读取游戏 / 模组的 `localisation/*.yml` 才能显示中文
（`text_l_english.yml` 是主要词条来源，约 1 万条）。
这些 yml 文件本身也使用了非 UTF-8 的编码，解析器已提供对应解码能力。

### C9 视图口径（阶段 4，最终版，覆盖 C6 的表）

| 视图 | 底色 | 斜线 |
|------|------|------|
| 政治 | 拥有国颜色 | 占领国颜色；**叛军不画** |
| 宗教 | 该省自身的宗教颜色 | **实际在场的信仰**（被占领取占领国，否则取拥有国）与省宗教不同时 |
| 文化 | 该省自身的文化颜色 | **无**（明确要求） |
| 发展度 | 越高越绿、越低越红 | 无 |
| 王朝 | 统治王朝的**生成色** | **无** |
| 神罗 | 帝国外用中性灰；帝国内按皇帝/选帝侯/自由市/成员国分色 | 占领国**不在帝国之内**时 |
| 战斗 | 陆地白→红，海洋**蓝→红**，均为历史累计（`1 + 0.3 × 惨烈度`） | 无 |
| 科技 / 思潮 | 仅存档当日快照（相对着色），按钮与主视图**同排** | 思潮：正在接纳的省份画高一级颜色 |

新增视图的两个依据问题及结论：

* **王朝没有官方色表**。本机 268 个模组无一提供 `common/dynasties/`，存档的
  `dynasty` 区块只是按 `culture_group` 分组的随机名池。颜色按字母序下标用
  黄金角散列生成，确定且可复现。
* **神罗没有自由市名单**。`government_name` 匹配 `/free_city/i` 得到 10 个；
  成员国身份由首都省份的 `hre` 推导，重放结果与存档字段在存档日期
  **129/129 完全一致**（已入测试）。

### C10 重放必须叠加"无日期"的初始状态

省份区块存的是**战役最终**数值，重放策略是从存档当日往回推。但 4,941 个省里
有 **2,450 个**的归属只存在于 `history` 的**无日期**初始项中，而不是
`1444.11.11` 的带日期事件里。任何只消费带日期事件的重放都会把这些省冻结在
存档当日的归属上——曲线会变成一条直线（俄罗斯 2,249 → 2,426 而非真实的
111 → 2,505）。凡是"从存档倒推"的聚合都必须先叠加初始状态。

### C11 长期曲线只能由省份历史聚合

`income_statistics` / `nation_size_statistics` 等账本系列只有约 45 年滚动窗口，
收入/兵力/理念/正统性只有快照，科技只有快照。因此 130 年的兴衰曲线**只能**用
逐月重放的 `base_tax + base_production + base_manpower` 与省份数表示。
重放到存档日期时，聚合值可能与省份区块的静态值有约 4% 的差异（部分开发度变化
未写入省份历史），曲线形状可信、绝对值以存档字段为准。

## 非目标（当前阶段）

* 不做多人账号体系；这是个人站点。
* 不修改存档（只读解析 + 展示）。
* 不追求与游戏内 UI 完全一致。
